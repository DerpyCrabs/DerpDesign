# Editing and verification

1. List projects/demos; activate the intended demo in the owned headless workspace. Use the desktop only for explicitly requested desktop actions. Do not change a declaration just to accommodate ordinary styling/code changes.
2. Use `pane_inspect` by selector or point to retrieve actual DOM/CSS/geometry. Use `pane_capture` for a PNG and versioned evidence record. Inspect the returned image, not just the existence of a file. If connected tool images are unavailable, the helper returns the real capture path for the local image viewer.
3. Edit the actual target project source using ordinary coding tools. Respect existing uncommitted work. Integration code remains external. CSS may hot-update; application changes may reload. Reset/replay the declared scenario in the isolated host when needed.
4. Exercise the affected interaction using `pane_input`, then inspect and capture again. Verify each relevant viewport/engine and adjacent existing interactions. Use `derpdesign sequence` to save reproducible inputs, assertions and capture evidence instead of repeatedly writing temporary MCP scripts. Check normal/hover/focus states, menu separators, dismissal and drag cancellation where affected. Readiness waits and capture generation/source fingerprints protect evidence, but a successful capture is not proof that the design meets the request; inspect its content.
5. Before handoff, compare the images with the supplied/reference UI and all user corrections; distinguish verified behavior from unimplemented fixture/native behavior.
For a delegated integration test, use a reversible, narrowly scoped source edit, verify it through real MCP, then restore only that edit and verify restoration. Do not discard pre-existing changes.

Ladybird point picking descends into same-origin frames and returns `element.framePath`. Pass that array with subsequent selector inspections; selectors are relative to the selected frame, while bounds remain in the pane viewport. Cross-origin frames stop at the iframe boundary. `geometryOnly: true` retrieves lightweight hover geometry, not full DOM/CSS evidence; omit it when verifying source changes. Renderer crashes are explicit errors and require reset before further evidence is valid. MCP does not yet expose full console/network/performance histories; consult `docs/ladybird-diagnostics.md` before attributing a failure upstream.
